# 一、C 语言（★ 优先级最高，简历明确写了"指针、结构体、位操作"）

## 1.1 指针

**Q6 ★ 指针和数组的区别？`a` 和 `&a` 有什么区别？**
> 数组名在大多数场合会退化成"首元素地址"，但它**不是指针变量**——不能 `a++`，`sizeof(a)` 得到的是整个数组大小，而 `sizeof(指针)` 是 4 或 8 字节。
> 对数组 `int a[10]`：`a` 的类型是 `int*`（指向首元素），`&a` 的类型是 `int(*)[10]`（指向整个数组）。所以 `a+1` 前进 4 字节，`&a+1` 前进 40 字节。

**Q7 ★ 指针运算：`p+1` 到底移动多少字节？**
> 移动 `sizeof(*p)` 个字节。`int* p` 加 1 是 4 字节，`char*` 加 1 是 1 字节，`struct S*` 加 1 是 `sizeof(struct S)`。**指针的类型决定步长**——这也是嵌入式里"用 `uint8_t*` 遍历缓冲区"的原因。

**Q8 ★ 指针做函数参数，为什么能改变外面的值？**
> C 是**值传递**：传进去的是地址的**副本**。但副本里装的是同一个地址，所以 `*p = x` 改的是同一块内存。反过来，如果函数里写 `p = &y`，只改了副本，外面的指针不动——**要改指针本身，得传二级指针 `**p`**。

**Q9 `const char *p` 和 `char * const p` 有什么区别？**
> 从名字往里读：`const char *p` → `*p` 是 const，**指向的内容不能改**，指针本身能改（指向别处）。`char * const p` → `p` 是 const，**指针本身不能改**，内容能改。`const char * const p` 两个都不能改。

**Q10 ★ 函数指针有什么用？（嵌入式里很常见）**
> 用来做**回调**和**跳转表**。比如：中断向量表本质就是函数指针数组；用函数指针实现"状态机里每个状态对应一个处理函数"，避免一大串 if-else。写法：
> ```c
> typedef void (*handler_t)(void);
> handler_t tbl[3] = {state_idle, state_run, state_stop};
> tbl[cur]();
> ```

**Q11 什么是野指针？怎么避免？**
> 指向"已经释放或不确定"内存的指针。常见两种：`free(p)` 之后没置 NULL；局部指针没初始化就用。
> 避免：**定义时初始化成 NULL；free 之后立刻 `p = NULL`；使用前判空。**

**Q12 空指针和悬空指针的区别？**
> 空指针＝值为 NULL，**能判断**（`if (p)`），解引用会崩；悬空指针＝指向已释放内存，**值不一定是 NULL，判断不出来**，更危险。

## 1.2 结构体

**Q13 ★ 结构体为什么要内存对齐？`sizeof` 为什么比字段加起来大？**
> CPU 按字长（4/8 字节）成块读内存，不对齐就要拆两次读，甚至在某些 ARM 上直接触发异常。所以编译器自动在字段之间塞填充字节。
> 例：`struct { char a; int b; char c; }` 在 32 位上 `sizeof` 是 **12**，不是 6。

**Q14 怎么减小对齐带来的浪费？**
> **把大的成员放前面**（`int b; char a; char c;` → 8 字节）。或者用 `#pragma pack(1)` / `__attribute__((packed))` **强制不对齐**——协议解析（比如 Modbus、网络包）必须这么做，否则结构体和字节流对不上。

**Q15 ★ 结构体传参为什么建议传指针？**
> 传值会把整个结构体**拷贝一份**（压栈），结构体一大就是纯粹的开销，还可能爆栈。传指针只传 4 字节，还能在函数里改原数据。**如果不想被改，用 `const struct S *p`。**

**Q16 位域（bit field）是什么？什么时候用？**
> 在一个字节/字里按位分配字段，比如 `struct { unsigned int mode : 2; unsigned int en : 1; }`。省内存、**直接对应寄存器布局**。缺点是布局依赖编译器实现，跨编译器不可移植。

**Q17 `typedef struct` 和 `struct` 有什么区别？**
> `struct S {}` 定义类型，用时必须写 `struct S`；`typedef struct {} S_t;` 可以直接用 `S_t`。**只是写法方便，本质是同一个类型。**

## 1.3 位操作（★ 嵌入式最高频）

**Q18 ★ 给一个 32 位寄存器，怎么把第 5 位置 1、清 0、取反？**
> ```c
> reg |=  (1U << 5);      // 置 1
> reg &= ~(1U << 5);      // 清 0
> reg ^=  (1U << 5);      // 取反
> if (reg & (1U << 5))    // 判断
> ```
> **口诀：置位用"或"，清零用"与非"，取反用"异或"，判断用"与"。**

**Q19 ★ 怎么只改某几位、不动其他位？（读-改-写）**
> ```c
> reg = (reg & ~(0x7 << 3)) | (val << 3);   // 改 bit3~bit5
> ```
> 先清目标位（与上一个"只有目标位为 0"的掩码），再或上新值。STM32 标准库里的 `GPIO_Init` 后面接 `BSRR/BRR` 寄存器就是这个思路的硬件版。

**Q20 ★ 用一个变量表示 8 个开关状态，怎么存？**
> 用 `uint8_t flags`，每位一个开关：`flags |= (1<<n)` 打开，`flags &= ~(1<<n)` 关闭，`(flags>>n)&1` 读。**比 8 个 `bool` 省 7 字节**，还能整字节一次传给协议。

**Q21 ★ 怎么交换两个变量的值不用临时变量？有什么坑？**
> ```c
> a ^= b; b ^= a; a ^= b;
> ```
> 坑：**当 `a` 和 `b` 是同一个变量（同一个地址）时，结果会被清零**。移动端/嵌入式的实际代码里，直接用临时变量更安全、可读性也更好。

**Q22 怎么判断一个整数是不是 2 的幂？**
> `n && !(n & (n-1))`。2 的幂只有一位是 1，减 1 之后那一位变 0、后面全变 1，按位与一定是 0。

**Q23 二进制、十进制、十六进制在嵌入式里怎么用？**
> 寄存器位图看**二进制**（哪一位是什么一眼看出），寄存器地址/掩码写**十六进制**（`0x40011000` 比十进制好读），范围/计数用十进制。**代码里养成写 `0x` 和 `U` 后缀的习惯**，避免隐式提升出问题。

## 1.4 关键字与内存

**Q24 ★ `volatile` 是干什么的？（几乎必问）**
> 告诉编译器"**这个变量随时可能被外部改变，每次都去内存读，别优化进寄存器**"。
> 三个必用场景：① 中断服务函数里改的变量（主循环里读）② 硬件寄存器 ③ 多线程共享变量。
> 我这边的实例：串口中断往环形缓冲里写 `head`，主循环读 `head`，不加 volatile 编译器可能把 `head` 缓存在寄存器里，主循环就永远看不到新数据。

**Q25 ★ `static` 的三个作用？**
> ① 修饰**局部变量**：生命周期变长（程序全程），但作用域仍在本函数——**函数内的"全局变量"**，常用于保存状态；
> ② 修饰**全局变量/函数**：链接属性变内部，**只在本文件可见**，避免命名冲突；
> ③ 在 C++ 里还能修饰类成员（嵌入式 C 不涉及）。

**Q26 `const` 有什么用？**
> 只读。除了防止误改，还能让编译器把数据放**只读段（Flash）**，省 RAM——嵌入式里常量表加 const 很有意义。另外 `const` 修饰指针参数是"我保证不改你的数据"的契约。

**Q27 ★ 栈和堆的区别？嵌入式里为什么尽量少用 malloc？**
> 栈：编译器自动分配释放，函数返回就没了，**大小固定（启动时定好）**，放局部变量。
> 堆：`malloc/free` 手动管理，**大小不固定但会碎片化**。
> 嵌入式少用 malloc 的原因：① 内存小，碎片化后分配失败 ② 没有 MMU 保护，野指针直接改坏别人 ③ malloc 失败要处理，很多人忘了判空 ④ 实时性不可控（分配时间不确定）。**常用方案：静态分配 / 内存池。**

**Q28 ★ 内存泄漏在单片机/Linux 上分别是什么后果？**
> Linux 上进程泄漏多了会被 OOM 杀掉，或者把整机拖慢；单片机上更直接——**堆越用越少，最后 malloc 返回 NULL**，程序跑飞。所以我做智能家居那边特别注意"每个 open/init 都要有对应的 close/deinit"。

**Q29 大小端是什么？怎么判断？**
> 小端：低位字节放低地址（x86、ARM 默认小端）；大端：高位字节放低地址（网络字节序）。
> 判断：
> ```c
> int x = 1;
> if (*(char*)&x == 1) 小端; else 大端;
> ```
> 通信里必须注意——Modbus 就是**大端**传数据（高位在前）。

**Q30 宏定义带参数有什么坑？**
> ① 参数没加括号 → `#define SQ(x) x*x`，`SQ(1+2)` 变成 `1+2*1+2`；
> ② 多条语句的宏没包 `do{...}while(0)`，放进 `if` 里会出错；
> ③ 宏没有类型检查。**能用 `static inline` 就别用宏。**

**Q31 `sizeof` 是函数吗？`sizeof(int)` 在 32 位和 64 位系统上一样吗？**
> 不是函数，是**编译期运算符**，不产生运行时开销。`sizeof(int)` 一般都是 4；但 `sizeof(long)` 32 位是 4、64 位是 8，`sizeof(指针)` 4/8。**所以跨平台代码不要假设指针是 4 字节。**

**Q32 ★ 一道经典题：`char *s = "abc"; s[0] = 'A';` 会怎样？**
> 崩溃或未定义行为。因为 `"abc"` 是**字符串常量，放在只读段**（`.rodata`）。要改应该写成 `char s[] = "abc";`（数组在栈上，可改）。

**Q33 怎么求数组元素个数？传进函数后还能这么求吗？**
> `sizeof(arr)/sizeof(arr[0])`。**传进函数后就失效了**——数组名退化成指针，`sizeof` 得到的是指针大小。所以函数里必须额外传长度（或者用末尾哨兵）。

# 二、STM32 外设（简历：GPIO / TIM / USART / NVIC，标准外设库）

**Q34 ★ 讲一下 STM32 启动到进入 main 的过程。**
> 上电 → 从 Flash 的 `0x08000000`（或映射地址 `0x00000000`）取**栈顶值**放进 MSP → 取**复位向量**跳到 `Reset_Handler`（在启动文件里，汇编）→ 初始化 `.data`（从 Flash 拷到 RAM）、清零 `.bss` → 调用 `SystemInit()`（配时钟）→ `__libc_init_array()`（调构造函数）→ `main()`。

**Q35 ★ STM32F103 的时钟怎么配到 72MHz？（简历写了 72M）**
> 8MHz 外部晶振 → PLL 倍频到 72MHz。HSE 8M ÷1（HSE 不分频）× 9 = 72MHz，作为 SYSCLK；AHB 不分频（72M）；APB1 最大 36M（÷2）；APB2 = 72M。**标准库用 `SystemInit()` + `RCC_Configuration()`，或者 CubeMX 生成。**

**Q36 ★ GPIO 有哪几种模式？推挽和开漏的区别？**
> 输入：浮空、上拉、下拉、模拟（ADC 用）。
> 输出：推挽、开漏；再加复用推挽/复用开漏。
> **推挽**：能主动输出高和低，驱动能力强；**开漏**：只能拉低，高电平靠外部上拉——适合**总线（I2C）和多设备共线**。

**Q37 为什么 LED 常接成"低电平点亮"？**
> 因为 MCU 引脚的**灌电流能力通常大于拉电流**，低电平时电流从 VCC 经 LED 流入引脚，更亮更稳。也可能是硬件已定，软件只是配合。

**Q38 ★ 定时器怎么算定时时间？（简历有 PSC/ARR 的话必问）**
> `T = (PSC+1) × (ARR+1) / f_clk`。
> 例：72MHz、PSC=7199、ARR=9999 → 计数频率 = 72M/7200 = 10kHz，10kHz 数 10000 次 = **1 秒**。

**Q39 PWM 的频率和占空比分别由什么决定？**
> 频率由 `(PSC+1)×(ARR+1)` 决定；占空比由比较寄存器 CCR 决定（`CCR/(ARR+1)`）。改占空比只动 CCR，不用改 ARR——这样频率不变、电机不抖。

**Q40 ★ 中断和轮询的区别？什么时候用哪个？**
> 轮询：主循环不停查标志，简单但占 CPU，响应不及时。
> 中断：事件来了才打断 CPU，实时性好，但要考虑**优先级、临界区、重入**。
> 我的原则：**实时性要求高的（串口收数、按键、定时）用中断；慢速、可等待的（传感器读数显示）用轮询。**

**Q41 ★ NVIC 是干什么的？抢占优先级和子优先级有什么区别？**
> NVIC 管中断的**使能、挂起、优先级**。
> 抢占优先级高的可以**打断**正在执行的低优先级中断；子优先级**不能打断**，只在同时挂起时决定谁先执行。**STM32 用 4 位表示优先级，要先用 `NVIC_PriorityGroupConfig` 划分抢占/子优先级的位数。**

**Q42 ★ 中断服务函数（ISR）里为什么不能做耗时操作？**
> ISR 会打断主流程，做太久会导致：① 其他中断被延迟（丢失数据）② 主循环卡顿 ③ 优先级反转/看门狗复位。
> 正确做法：**ISR 里只做"取数据 + 置标志"，处理放到主循环**（这也是我用环形缓冲 + 超时判断的原因）。

**Q43 中断里能不能用 printf / malloc？**
> 不能。`printf` 是阻塞的、可能用到不可重入的缓冲；`malloc` 不是可重入的，会破坏堆。**ISR 里只用简单的赋值、置标志。**

**Q44 什么是中断嵌套？什么时候会出问题？**
> 高优先级中断打断低优先级中断。问题：共享变量被两边同时改 → 数据错乱。解决：**临界区关中断（`__disable_irq()` / `__set_PRIMASK`）保护共享资源，或者用 volatile + 原子操作（单字节/单字读写本身就是原子的）。**

**Q45 标准外设库和 HAL 库的区别？你用的哪个？**
> 标准库（StdPeriph）直接操作寄存器封装，**代码小、执行快、看得清寄存器**，适合 F1 这类资源紧的片子；HAL 抽象层次高、跨系列可移植、配 CubeMX 快，但**代码大、有额外开销**。我用的是标准库，所以对寄存器布局更熟。

# 三、串口通信 + 环形缓冲 + 超时（★ 简历核心卖点，必深挖）

**Q46 ★ 串口一帧数据怎么组成？波特率是什么？**
> 起始位（1 位低） + 数据位（8/9 位） + 校验位（无/奇/偶） + 停止位（1/1.5/2 位）。
> 波特率 = 每秒传输的**位数**，比如 9600 表示每位 104μs。**收发双方必须一致**，不一致就是乱码。

**Q47 ★ 为什么串口接收要用"中断 + 环形缓冲"？**
> 串口数据是**突然来的**，而主循环在干别的事（读传感器、刷屏）。如果轮询等串口，主循环就被阻塞；如果在中断里直接处理命令，又违反"ISR 要短"。
> 所以：**中断负责"收字节塞进缓冲区"（快进快出），主循环负责"从缓冲区取出来解析执行"**。这是标准的**生产者-消费者**模型。

**Q48 ★ 环形缓冲为什么比普通数组好？**
> 读写指针各自前进，**写到末尾绕回开头，不需要搬数据**。普通数组要么越界，要么每次取完得把剩余数据 `memmove` 到开头（O(n) 拷贝，还阻塞）。

**Q49 ★ 环形缓冲满了怎么办？**
> 必须有明确策略，不能说"不会满"：① **丢最旧的**（覆盖写，适合实时控制类数据）② **丢最新的**（保留历史）③ **置溢出标志 + 计数**，主循环发现后报警/清空。我的实现里保留了写满标志，主循环检测到就丢弃这一帧并重新同步。

**Q50 ★ 环形缓冲为什么"读写指针用单字节/单字"就安全？**
> 因为 `uint8_t head` 的读写**在总线上是原子的**（一条指令完成），不会出现"读到一半被中断改掉"的情况。但如果用 16/32 位且不是字对齐，或者用了复合操作（`head++` 本质是读-改-写），就要进临界区。**实践里：单生产者单消费者 + 单字节索引，不加锁是安全的。**

**Q51 ★ 你简历写"10s 超时保护"，为什么需要？怎么实现？**
> 场景：蓝牙遥控的小车，一旦**信号断了（超距离、手机没电、模块掉线）**，它会一直保持最后一条指令往前冲——很危险。
> 实现：每条指令到达时记录 `last_rx_tick = HAL_GetTick()`（或自己用 SysTick 计数）；主循环里判断 `now - last_rx_tick > 10000` → 停车并把状态机复位。**要点：超时判断必须放主循环，不能放中断。**

**Q52 ★ 串口乱码/收不到，你怎么排查？**
> 分层查：① **硬件**：TX/RX 是否交叉接反、共地没有、电平对不对（TTL/RS232）、线有没有断 ② **参数**：波特率、数据位、校验、停止位是否一致 ③ **程序**：引脚复用是否配成 USART（`GPIO_PinAFConfig`）、USART 时钟和 GPIO 时钟是否使能、`USART_Cmd` 有没有打开、中断优先级和 `NVIC_EnableIRQ` 有没有漏 ④ **数据层**：先发固定字节（0x55）用逻辑分析仪看波形，确认时序和波特率。
> **我的习惯：先用串口调试助手自发自收确认线，再单步看寄存器。**

**Q53 什么是"丢包"？你遇到过怎么解决的？**
> 数据没收到或收到一半。原因：处理太慢导致**溢出（ORE 标志）**、中断优先级被抢占太久、缓冲太小。
> 解决：加大缓冲、ISR 里只搬字节、开 ORE 中断并在出错时清标志重同步、降低波特率或改成 DMA。

**Q54 DMA 和中断接收串口有什么区别？**
> 中断方式每个字节都要进一次 ISR（几十次上下文开销）；DMA 由硬件把数据搬到内存，**只在半满/全满时中断一次**，CPU 占用低。缺点是配置复杂、调试时不容易看清状态。**数据量大或高波特率用 DMA，小数据量中断就够。**

**Q55 未知字符你是怎么"忽略"的？**
> 在解析状态机里：对首字节做合法性判断（比如必须是 `0xAA` 帧头），不匹配就**丢弃并回到"等帧头"状态**，而不是报错退出。这样既能防误触发，又能自动重新同步。

# 四、Modbus RTU + CRC-16（★ 简历明确写了"报文构造与解析、手写 CRC-16"）

**Q56 ★ Modbus RTU 一帧长什么样？**
> `地址(1B) + 功能码(1B) + 数据(N) + CRC(2B)`，**CRC 低字节在前**。帧与帧之间靠**至少 3.5 个字符时间的静默**分隔（RTU 靠时间间隔划分帧，不靠特殊字符）。

**Q57 ★ 举个例子：读从站 0xFE 的保持寄存器 0x000F，1 个寄存器。**
> `FE 03 00 0F 00 01` + CRC。CRC 算出来是 `A0 06`（低字节 A0 在前），所以完整帧是 `FE 03 00 0F 00 01 A0 06`。
> 从站应答：`FE 03 02 xx xx CRC`（02 = 返回字节数，xx 是寄存器值）。

**Q58 ★ 常用功能码有哪些？**
> `01` 读线圈、`02` 读离散输入、`03` **读保持寄存器**、`04` 读输入寄存器、`05` 写单个线圈、`06` 写单个寄存器、`0F` 写多个线圈、`10` 写多个寄存器。

**Q59 ★ CRC-16/Modbus 的参数是什么？怎么算？**
> 初值 `0xFFFF`，多项式 `0xA001`（这是 0x8005 的反转形式），**输入/输出都反转，结果不异或**。
> 算法（我手写的版本）：
> ```c
> uint16_t crc16(const uint8_t *buf, int len) {
>     uint16_t crc = 0xFFFF;
>     while (len--) {
>         crc ^= *buf++;
>         for (int i = 0; i < 8; i++) {
>             if (crc & 1) crc = (crc >> 1) ^ 0xA001;
>             else         crc >>= 1;
>         }
>     }
>     return crc;   // 低字节先发
> }
> ```

**Q60 为什么用 CRC 而不是"累加和"校验？**
> 累加和太弱：两个字节互换、或者人为改动一对值，和可能不变。CRC 本质是多项式除法取余，**能检出绝大多数随机错误和突发错误**，代价只是几十条指令。

**Q61 ★ 收到一帧怎么判断对不对？**
> ① 长度够不够（至少 4 字节）② 地址是不是自己 ③ 功能码支不支持 ④ **重新算一遍 CRC，和帧尾两个字节比对（注意低字节在前）** ⑤ 功能码最高位是 1 说明从站返回了异常码，要按异常处理。

**Q62 Modbus 是一问一答还是可以主动上报？**
> **标准 Modbus 是主从一问一答**，从站不能主动发。所以我的采集程序是主站定时轮询 9 类传感器，按地址 + 寄存器区分。

**Q63 多个从站挂在一条 485/串口上，怎么区分？**
> **靠从站地址**。每条命令的第一字节是目标地址，只有地址匹配的从站才应答（`0x00` 是广播，从站不应答）。所以地址不能重复。

# 五、电机驱动与 PWM（简历：L9110S 双 H 桥、PWM 差速）

**Q64 ★ H 桥为什么能正反转？**
> 四个开关组成 H 形：左上+右下导通 → 电流左→右（正转）；右上+左下导通 → 电流右→左（反转）。**切换电流方向就切换转向。**

**Q65 ★ 死区是什么？为什么需要？**
> 换向瞬间如果上下桥臂**同时导通**，电源直接短路（叫"直通"），会烧管子。所以驱动芯片/程序里要插入一小段"全关"的时间，即**死区**。L9110S 内部有逻辑保护，但 PWM 频繁换向时仍要注意。

**Q66 ★ 两个电机怎么实现转向？（差速）**
> 靠**左右轮转速差**：两轮同速正转 → 直行；左慢右快 → 右转；左反转右正转 → 原地转。所以给两个电机两组 PWM + 两个方向引脚就行。

**Q67 PWM 频率对电机有什么影响？**
> 太低（<1kHz）电机会叫、有抖动、能听到噪音；太高开关损耗大。**常用 10–20kHz**（超过人耳听觉，安静）。我用的是几十 kHz 量级，占空比 0–100% 线性对应速度。

**Q68 为什么不直接用 GPIO 高低电平驱动电机？**
> ① 电流不够（MCU 引脚几十 mA，电机几百 mA 到几 A）② 电机是感性负载，断电瞬间反电动势会打穿 IO ③ 无法调速。所以要驱动芯片 + PWM。

# 六、传感器与外设（TCRT5000 / HC-05 / 数码管）

**Q69 ★ TCRT5000 怎么循迹？为什么用两路？**
> 红外发射 + 接收对管：**白面反光强 → 接收管导通 → 输出低；黑线吸光 → 输出高**（具体极性看模块）。
> 两路一左一右放在黑线两侧，组合判断：
> ```
> 左白右白 → 直行（两个都在黑线外或都在线内）
> 左黑右白 → 车身偏右 → 左转修正
> 左白右黑 → 车身偏左 → 右转修正
> ```
> 只用一路没法判断"偏哪边"，只能判断"有没有线"。

**Q70 HC-05 怎么配？AT 模式是什么？**
> HC-05 是**蓝牙串口透传模块**：配对成功后，手机发什么，模块就从 TX 吐什么，MCU 当成普通串口收。
> AT 模式（KEY 脚拉高上电，波特率固定 38400）用来配置：`AT+NAME` 改名字、`AT+PSWD` 改配对码、`AT+ROLE=1` 设主/从、`AT+UART` 设通信波特率。**注意：AT 模式和透传模式的波特率是两套。**

**Q71 ★ 数码管动态扫描是什么？为什么要消隐？**
> 8 位数码管共用段选线，靠**位选轮流点亮**（每位点亮 1–2ms），利用人眼视觉暂留看起来是同时亮。
> **消隐**：切换下一位之前先把段选清零，否则上一位的段码会"串"到下一位上，看起来重影。
> 扫描太快亮度不够、太慢会闪；常见每位 1ms、整屏 8ms（125Hz）。

**Q72 限流电阻/驱动芯片为什么需要？**
> 数码管每段电流几 mA 到几十 mA，8 位一起点亮会超过 MCU 总电流限制。所以用三极管/驱动芯片（如 74HC595、ULN2003）扩流。

# 七、嵌入式 Linux（简历：framebuffer / mmap / 串口驱动 / PWM）

**Q73 ★ framebuffer 是什么？怎么画一张图？**
> 一块**显存**，应用层拿到它就能直接写像素。`open("/dev/fb0")` → `ioctl(FBIOGET_VSCREENINFO)` 拿分辨率/bpp → `mmap` 映射到用户空间 → **往映射出来的地址写 RGB 数据** → 屏幕就显示了。写像素的偏移算法：`offset = (y * xres + x) * (bpp/8)`。

**Q74 ★ mmap 是干什么的？为什么用它而不是 read/write？**
> 把**内核的物理内存映射到用户进程的地址空间**，之后读写就是直接访问内存，不用每次 `read()` 拷贝一次。
> 显示/摄像头这类**大块连续数据**用 mmap 效率高得多；`read()` 每帧都要 memcpy 一次，还受页缓存影响。

**Q75 ★ mmap 用完为什么必须 munmap？不释放会怎样？**
> 映射会占进程的虚拟地址空间（32 位只有 3G 可用），频繁映射不释放会**地址空间耗尽**，`mmap` 返回 `MAP_FAILED`。另外映射对应的文件描述符也要 `close`。**"每个 open 有 close，每个 mmap 有 munmap"——这就是我简历里写的"显式释放资源、规避内存泄漏"。**

**Q76 ★ 写一个字符设备驱动的大致流程？**
> ① 定义 `file_operations` 结构（open/read/write/ioctl/release）② `register_chrdev` 或 `alloc_chrdev_region + cdev_add` 注册设备号和 cdev ③ 在 probe/init 里初始化硬件 ④ `class_create + device_create` 自动建 `/dev` 节点 ⑤ 卸载时反向释放（`cdev_del`、`unregister_chrdev_region`、`class_destroy`）。

**Q77 用户空间和内核空间怎么传数据？**
> 不能用普通指针互访（会缺页/崩溃），必须用 `copy_to_user()` / `copy_from_user()`——它们会做地址合法性检查。

**Q78 Linux 下怎么调 PWM？**
> 走 sysfs：`/sys/class/pwm/pwmchip0/` → `export` 一个通道 → 设 `period`（周期 ns）和 `duty_cycle`（高电平时间 ns）→ `enable=1`。或者用驱动里 `pwm_request/pwm_config/pwm_enable`。

**Q79 ★ 串口在 Linux 下怎么配成 raw 模式？为什么？**
> 终端默认是"行缓冲 + 回显 + 特殊字符处理"，直接收发二进制会出错。所以要：
> `cfmakeraw()` 或手动 `c_lflag &= ~(ICANON|ECHO|ISIG)`，再 `cfsetispeed/cfsetospeed` 设波特率，`tcsetattr` 生效。**还会用 `VMIN=1, VTIME=0` 控制 read 的阻塞行为。**

**Q80 Linux 下 read() 阻塞和超时怎么处理？**
> ① 打开时加 `O_NONBLOCK` 非阻塞 ② `select/poll/epoll` 等可读再 read ③ termios 里设 `VMIN/VTIME`。**做传感器轮询我用 select + 超时，避免程序卡死在 read 上。**

**Q81 智能家居项目里，模块之间怎么解耦的？**
> 按"**驱动层 / 业务层 / UI 层**"分：驱动层只负责"读出一个值"或"写一个值"（比如 `sensor_read()` 返回温湿度结构体），业务层做逻辑判断（超阈值报警），UI 层只负责把数字画到 framebuffer 上。**UI 不直接碰硬件，硬件改动不影响业务逻辑。**

**Q82 内存泄漏在 Linux 上怎么查？**
> ① 代码审查（open/malloc 是否都有对应释放）② `valgrind --leak-check=full` ③ `top/ps` 看 RSS 是否持续上涨 ④ `/proc/<pid>/maps` 看映射数量。**最土但有效：让程序跑一整夜，看内存曲线。**

# 八、VisionPro + C#（项目①，技术面会问但不会太深）

**Q83 CogPMAlign 是干什么的？为什么定位要用它？**
> **模板匹配**：先"训练"一个模板（把目标区域圈出来），运行时在图像里搜索最相似的位置，输出坐标和角度。后续所有检测工具用 `CogFixture` **跟随这个坐标**——工件位置变了也不用改参数，这就是"随动"。

**Q84 CogFixture 随动坐标是什么原理？**
> 输入一个坐标系（比如 PMAlign 输出的位置 + 角度），**把它的原点/角度变换应用到后续工具上**。平移 + 旋转后，后续工具就在"工件的局部坐标系"里工作，实现了"位置无关"。

**Q85 CogBlob 怎么统计骰子点数？**
> 先二值化（阈值分割）把亮点分离出来，`CogBlob` 统计**连通域个数和面积**。骰子每个点是独立亮斑，所以**亮斑总个数就是点数**（7 颗骰子共 28 点）。要过滤噪点就加**面积上下限**。

**Q86 CogColorMatch 识别颜色怎么做的？**
> 对每个位置取一小块 ROI，和预先训练的颜色样本比相似度，输出匹配分数和颜色名。**关键：光照稳定 + 每个颜色都要训练多个样本**，否则色差大就误判。网线 7 色，我就配了 7 组。

**Q87 CogToolBlock 是什么？为什么用它能"算法与界面解耦"？**
> 它是一个**容器**，把多个工具（3 个 PMAlign）封装成一个"黑盒"，对外只暴露输入/输出。这样：① 界面上不用管内部怎么实现 ② 换算法只改 ToolBlock，C# 代码不动。**这就是封装思想在视觉里的体现。**

**Q88 C# 怎么调用 VisionPro 作业（.vpp）？**
> 引用 `Cognex.VisionPro` 系列 DLL → `CogSerializer.LoadObjectFromFile(".vpp")` 反序列化成 `CogToolBlock`（或 `CogJob`）→ 把图像塞进输入 `Inputs["Image"].Value = cogImage` → `Run()` → 从 `Outputs["Result"].Value` 取结果。

**Q89 图像怎么从相机/文件进到 VisionPro？**
> 文件：`new CogImage8Grey(new Bitmap(path))` 或 `CogImageFileTool`；相机：用 `CogAcqFifoTool` 采一帧。注意**灰度 vs 彩色**要选对类型。

# 九、调试与工具（简历写了分层排查、串口日志、示波器/逻辑分析仪）

**Q90 ★ 你简历写"按硬件→驱动→参数→应用分层排查"，举个例子。**
> 比如小车不动：① **硬件**：量电源电压、看电机线、看驱动芯片有没有发烫 ② **驱动**：用万用表/示波器看 PWM 引脚有没有波形、频率对不对 ③ **参数**：占空比是不是 0、方向引脚电平对不对 ④ **应用**：指令解析出来的速度值有没有被状态机覆盖成 0。**每一层都有"看得见的信号"，不靠猜。**

**Q91 示波器和逻辑分析仪分别什么时候用？**
> **示波器**看**模拟质量**：PWM 波形、上升沿、纹波、电源噪声、串口电平是否符合 TTL 规范。
> **逻辑分析仪**看**协议时序**：串口/I2C/SPI 的字节流解码，能直接解出"发的是什么字节"，排协议问题最快。

**Q92 程序跑飞/死机了怎么查？**
> ① 看有没有 HardFault（进 `HardFault_Handler` 打断点，看 LR/PC/栈）② 有没有看门狗复位（查 RCC 复位标志）③ 串口日志打印到哪一步停的（**定位到最后一条日志就是出错点附近**）④ 怀疑栈溢出就查 `_estack` 和 SP 的距离 ⑤ 怀疑中断风暴就数中断次数。

**Q93 怎么验证你的程序"长时间运行稳定"？**
> 让它在实验室跑一整夜/几天，记录：内存占用（RSS）、进程崩溃次数、传感器数据是否有跳变、串口有没有丢帧。**我简历里写"长时间运行稳定"，就是这么验的。**
